# HC-00 隔離實戰交接

目前已完成 demo 的自動化後端、客戶端 SDK 與瀏覽器驗證。人員現場實戰尚未執行，玩家入口仍關閉。

## 可重現的本機操作

需求：Node 22、Java 21。在 `hunter-clash/emulator` 執行 `npm ci --ignore-scripts`，再執行 `npm run lab`。
啟動器固定 `demo-hunter-clash` 的 Auth 9098、Functions 5003、Firestore 8180；頁面為 `http://127.0.0.1:5199`。
終端會列出當次新挑戰編號與四個臨時帳號／密碼（參賽 A、參賽 B、見證、管理）。這些不是正式使用者，也不會從正式站匯入任何資料。
每次產生不同編號，不覆寫既有場次或角色。入口設定若已關閉或環境不符，即拒絕初始化；資料庫批次失敗時，只清除此次已建立的 Auth 使用者。
以不同瀏覽器視窗切換身分。Ctrl+C 關閉實驗室；啟動器不使用 emulator import/export，關閉後不保留 demo 資料。
此操作頁僅限本機，不能作為工作人員手机遠端入口或正式隔離部署的替代證據。

## 實戰驗收紀錄

每項需記錄操作者、日期、使用的 source commit／環境、挑戰編號、觀察與 PASS／FAIL；無紀錄者為 NOT RUN。遇 FAIL 時不得發布或開放入口。

|案例|操作|預期結果|
|---|---|---|
|正常流程|A 提交，見證開始並通過認證，管理填理由放行並結算|狀態依序轉移，只結算一次|
|確認取消|提交確認視窗選取消|結果與版本不變|
|兩端競爭|A／B 都讀同版本後各自提交|只接受一筆，另一方重新讀取|
|角色指派|未指派帳號讀取或操作；參賽者嘗試認證|拒絕，不產生帳本或統計|
|帳號撤權|載入後由測試主持者停用角色／Auth 帳號再操作|後端拒絕，畫面不能靠舊權限完成操作|
|爭議／風險 hold|見證標記爭議，或管理保留風險|不得結算；放行必須有理由與版本綁定|
|結算回應遺失|操作已入帳但客戶端未收到回應，重送原請求|一份帳本、一次統計；不額外加勝場|
|刷新失敗|結算已確認，但讀取新狀態中斷|提示重新讀取，不誤示操作尚未完成|
|結算鎖定|結算後再認證或修改風險|拒絕變更；更正另走補償設計|
|既有資料|比對測試前後的既有 Hunter 生涯、XP、天梯及信箱|沒有 HC 寫入或歸零|
|手機與登入|390px 寬度、切換身分、登入失效、登出|無橫向溢出，登出清除畫面與記憶體 Token|

## 隔離部署前仍缺少的證據

1. 指定獨立 Firebase／GCP 測試專案及可核對的部署身分，禁止沿用 bxh-arena 或 bxh-arena-beta 作 HC 的測試資料庫。
2. 準備獨立可部署的 HC adapter；目前 emulator bootstrap 的部署禁止必須保留，不能直接移除來上線。
3. 取得正式後端的實際 Functions 清單／各模組版本、Rules 發布版本及 IAM，與固定來源對照。個別模組部署成功不代表整包一致。
4. 在獨立部署驗證簽章、Token 撤銷、IAM、App Check、手機傳輸、實際人員操作及資料隔離，留下證據後再判定 internalBeta。

後端核對摘要見 deployment-audit.json。候選 run 36668868791 的 Functions／Rules 部署均 skipped；其他已部署模組不得拿來替代 HC 的驗收。
此文件是交接與待測標準，不能自動將 checkpoint 的完整驗收狀態改成 PASS。
