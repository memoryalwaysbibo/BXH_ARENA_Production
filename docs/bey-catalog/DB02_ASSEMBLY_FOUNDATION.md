# DB-02｜組裝相容性引擎第一批（2026-10-09）

## 完成
- 以資料結構定義五種已知配置：一般三件式、上盤／固鎖一體式、CX 三部件＋一體式下半部、CX 三部件＋獨立固鎖／軸心、CX 四部件＋獨立固鎖／軸心。
- 不允許多放或少放部件；同一 partId 不能重複。
- 未知結構返回 pending，不自動當成合法。
- 結構完整 ≠ 物理相容：缺少經核對的完整配置相容證據時返回 pending，不能保存為已驗證配置。
- 禁止因為零件尚在 research staging（selectable=false）就讓玩家選用。
- 版本化介面規則：不同版本不能混用；明確的已驗證不相容證據優先阻擋。
- 對 DATA-01B 研究資料的 16 組配置執行結構審核：15 組結構完整、1 組單一拆件待核對、0 組達到可供玩家配裝的物理相容驗證。此結果不代表 15 組可任意改裝。

## 重要界線
- 目前僅是純函式引擎與測試；尚未接上 ARENA 玩家配裝、Firestore、收藏、出戰排序。
- 不能只憑同系列／外站清單，推斷跨零件物理相容。
- 原廠原配可作後續逐組證據建立的來源，但要先核對版本與證據，不能直接將所有相似配置視為可搭。
- 配色版本、實際發售與賽規禁限用是獨立檢查，仍待後續批次。
- 未確認或誤判要保留待核對草稿與管理端修復路徑，不可刪除歷史資料。

## 回退
- 此 PR 新增獨立純函式與測試，修改 CI 測試命令；不改既有 UI 或正式 Firestore。
- 若 CI 失敗，保持 Draft 不合併。

## 第二批｜證據版本、修正與回退
- 新增 `assembly-rule-registry.cjs`：只有具備來源、查核人、查核時間、完整零件集合的規則，才可進入不可變的發布版本。
- 新增 `rule-change-impact.cjs`：管理員發布前預覽受影響的配置與狀態變化，不修改任何玩家收藏、歷史出戰或正式賽果。
- 發布採 `expectedActive` 比對，避免兩個管理員同時切換版本造成覆蓋。
- 回退不是刪除新版，而是重新啟用舊版並保留操作紀錄。
- 零件須明確 `selectable=true` 才可透過發布版本取得已驗證狀態；尚未發布的研究零件維持待核對。
- SHA-256 只作完整性檢查，**不是數位簽章，也不能取代後端授權、來源真實性或人工查證**。
