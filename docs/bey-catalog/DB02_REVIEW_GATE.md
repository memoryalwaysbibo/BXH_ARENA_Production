# DB-02｜兩人審核與發布安全閘門（2026-10-09）

## 本批交付
- 原配規則草稿經來源複核、審核說明、時間與人員紀錄後，才能產生第一階段審核計畫。
- 第二階段由不同的審核者獨立審查，禁止同一人自行核准。
- 草稿內容或證據被更動後，舊審核失效，必須重新確認。
- 審核通過仍只得到 ready_for_server_verification；永遠不自動發布或將零件標為可選。
- 原有的不可變版本、影響預覽與回退機制維持不變。

## 安全限制
- 本批純函式只接受 reviewerId、sourceRechecked 等輸入，**不能驗證使用者真實身分或來源真實性**。
- 任何前端傳入的 reviewerId、角色、來源複核結果都不得被後端直接信任。
- 未來須在受控後端以 Firebase Auth／IAM 重新驗證審核者身分、權限及證據；寫入審核歷程時使用原子交易。
- 正式發布還需要版本簽核、資料一致性檢查、影響預覽、回退準備與獨立發佈權限。
- 目前不包含正式 Firestore writer、管理端 UI、公開玩家圖鑑或自動更新服務。
- DATA-01B 真實 197 筆 Firestore Emulator 全量寫入仍未驗收完成。
