# Hunter License 2.0 — B5 實力回測

## 交付範圍

B5 新增標準賽實力資料診斷面板與離線逐場回測工具。正式實力分維持原本的 60% 勝率 + 40% 得分占比，以及至少 3 場、8 個有效 Round 的門檻；不改執照等級、XP 或 B6 規則。沒有預設候選公式，也沒有正式新權重。

目前正式載入來源沒有開賽前評等快照。候選分顯示「—」，不能宣稱已完成真實資料對手強度校正或已證明精準度提升。

## 畫面與資料規則

- 僅可信標準賽 Round 納入診斷，附魔與未知版本排除。
- 顯示目前來源／期間的基準分、可辨識對手數、身分覆蓋率、重複對手比例與最大單一對手占比。
- 對手依跨賽事 playerId 分組，不用姓名合併。未知身分保留缺失數。
- 顯示可辨識對手子集的逐場勝率及對手等權勝率，兩者使用相同子集；等權值只是重複對手偏差診斷，不是新實力公式。
- 勝率參考區間使用 Wilson 95% 區間，假設各場獨立。重複對手可能違反假設；區間不是實力分信賴區間。部分資料缺失時暫停區間與勝率結論。
- 明列開賽前評等缺失，禁止以現在的玩家評等回填歷史。

## 離線回測

```sh
node scripts/backtest-hunter-strength.cjs --input records.json --output report.json
node scripts/backtest-hunter-strength.cjs --input records.json --candidate candidate.cjs --output report.json
```

輸入為已授權、去識別化的玩家視角記錄陣列；需保留一致的匿名對手識別碼，才能評估重複對手。工具不讀寫雲端。輸出省略 playerId、matchKey、原始 Round 與評等快照。

候選模組必須明確匯出 `{version, evaluate}`，evaluate 收到依時間排序的當時歷史前綴，每項包含獨立副本 `record` 與開賽前 `rating`，回傳有限的 0–100 分。沒有模組時只回放正式基準分，候選保持空值。測試中的示範公式只驗證介面，不代表採用或校準。

開賽前評等輸入契約：

```json
{
  "matchStartedAt": 1000,
  "ratingSnapshot": {
    "source": "server",
    "verified": true,
    "version": "rating-version",
    "capturedAt": 900,
    "selfBefore": 1000,
    "opponentBefore": 1100
  }
}
```

時間為同一時基的毫秒數，capturedAt 必須嚴格早於 matchStartedAt。數值須有限，版本須為非空字串。這些欄位只是離線契約，verified 標記不能證明來源真實；可信匯出端必須先驗證來源與時間，正式載入器並未新增快照寫入／接受機制。

缺少快照、日期不明或混用評等版本時，候選評估停止。日期不明時，基準前綴仍可檢視，但跳動值及最大跳動為空，不能當成時間序列結論。合格前綴同時記錄新舊分與逐場跳動；尚未達正式門檻的前綴不出分。

## 驗收與後續校準

已驗證小樣本區間、重複對手集中度、快照時序與版本限制、逐場前綴回放、候選輸出範圍、資料更正／撤銷、正式分不變及報告去識別。核心回歸 21 組、production frontend 檢查、既有執照與附魔帳本測試通過。390px 測試資料檢視 30 種畫面組合無水平溢出；不等同真實登入帳號驗收。

正式新公式驗收前仍需：取得可信的歷史開賽前快照；按玩家、對手與時間切分校準及保留驗證資料；比較小樣本尖峰、逐場跳動、強弱對手與重複對手分層結果；記錄候選版本、樣本量、覆蓋率及接受標準。這次沒有真實歷史校準結果，不能據此設定正式新權重。
