# Official homepage R2 reader candidate

This is a new production implementation based on current main, not a restored lab branch. The production writer has passed its initial live parity check (backend #446). The R2 browser switch in `modules/main-app/homepage-r2.js` is **false**; no query parameter, storage flag, or lab transport enables it.

- Initial rollout scope is guest event homepage: 20-card summary, confirmed version document listener, latest delta or full reset, on-demand authority-checked detail. No R2 data is persisted in the R1 fast cache. A missed version/reset or uncertain connection clears the summary view; late requests are fenced. Pending authoritative projection uses bounded retry; terminal transport failure uses R1. Explicit complete catalog/search/filter uses existing R1 for the lobby visit; player homepage remains R1 until registration/detail parity is accepted. This is not yet a complete player/catalog migration.
- Backend requires callable `readArenaHomeR2` and exact version-document-only Firestore Rules access. Card, first and delta data stay service-private. Existing room actions use the existing public tournament authorization path; no private data or action permissions changed.
- Guest initial first-page, search and player mode must be verified on actual deployment before enabling. Required gates: backend reader and live Rules acceptance, live withdrawal latency, first/delta/reconnect/rollback on actual page, detail and search parity, installed iPhone/Android version handoff. No old offline lab reruns. Release switch changes must be a later reviewed change, with R1 preserved as rollback.
