# Concrete server start dispatch candidate

This candidate uses the existing generated referee-seat engine to initialize the current and next match on each physical court. The server reads canonical `tournaments/{code}` inside the same start transaction, checks draw and roster revisions, and passes one server timestamp through dispatch, start, snapshot linkage and partner debit. It accepts no browser-supplied court or match state. An existing played/scored match, general/test/team event or invalid physical-court count is rejected.

`createWiredRankedStart` composes the real bracket reader, real dispatcher and integrity-checked private Hunter reader. `createWiredHandler` exposes this composition to a server build; the registered Callable export remains disabled. There is no deployment, client control switch, release-control write or legacy fallback in this change.

The synchronized writer now sets `registrationStatus=started` and `tournamentPhase=live` on both roots, updates both JSON views, and closes required check-in using the same timestamp (preserving an earlier valid closure). Court initialization preserves existing reservations, activates current matches only and leaves future matches pending. The actual public cloud serializer also retains only bracket draw ID/revision; the real bracket reader normalizes default single/individual metadata exactly as that serializer does. Private referee/court lock fields stay private; public matches and courts use the cloud runtime's explicit allowlist.

Validation includes real engine single-elimination/multiple-court and round-robin reservation cases, stale draw/roster rejection, existing-play rejection, public projection privacy, metadata locking and an actual Firestore transaction through the concrete server composition. The emulator uses a synthetic private Hunter reader, so it does not establish compatibility with the latest production/private Hunter source. The exact current private bundle still requires build-time provisioning and provenance verification, including the medium-or-larger policy.
