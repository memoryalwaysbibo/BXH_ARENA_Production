# 備取升正取：臨時加購候選版本

2026-10-30。搭配後端 release/commerce/TICKET_EXPANSION.md，未啟用、未部署。

## 操作

票券房（state.meta.eventAuthority=ticket 或 ticketAccessV1.version=1）走獨立升正取流程。單列可升正取，也可勾選多位後按「勾選名單升正取」。後端先報價：有空位不收費；不足時顯示名額、每名額20元、合計、容量變更與待補繳條件，由主辦再次確認。取消不記帳、不異動名單。一般官方／社群房沿用原本流程。

前端不推算可收金額；確認送出前用 sessionStorage 保存同一筆 operationId／報價。網路結果不明時，下次操作先核對舊操作，不能改選後重建加購。切換帳號、模式、登入週期或房間後，舊回應不更新目前畫面。無法保存待確認操作就不送出。

票券房的容量欄位灰化，普通設定儲存保留原容量。舊免費+8的線上及本機 roster 路徑遇到 ticket authority 會拒絕；真正防繞過仍須完整後端 writer 與 Rules 整合。

## 發布前必須完成

- 玩家商城購券／發券／主辦授權、選券建房、開賽扣券、欠費清償與通知。
- 票券及容量後端寫入防護、完整 Rules、其他新增或匯入入口、報名與自動補位整合。
- 舊合約黑爸2測試資料轉接；不能先刪除舊入口製造空窗。
- 手機與桌機真實 ticket room 瀏覽器驗收。單元測試不能取代實際可用的票券房驗收。

PR #655 的「簽約主辦購買場次」仍是舊方案草稿，本候選不基於該草稿；不要合併它來啟用新的玩家購券模式。
