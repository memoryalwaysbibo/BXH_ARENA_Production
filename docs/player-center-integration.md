# 個人中心整合候選版

「我的資料」預設進入個人總覽，保留基本資料、家庭資料與稱號入口，新增依賽事彙整的生涯紀錄。原我的賽程、獵人檔案、天梯入口照常使用。

## 資料契約

- 使用既有本人 Hunter cache 與註冊／公開摘要 cache，不新增集合、不變更結算、XP、階級或 H2H 公式。
- 總覽勝敗採正規賽已完成 Match，包含一般及積分賽；使用 Hunter 原有去重、更正、撤銷及輪空排除。賽事數指至少有一場完成對戰的活動，並非全場已完賽。
- 本季／生涯是個人中心局部篩選，不改獵人檔案的來源與期間。缺少賽季起點時本季數值顯示破折號，日期未明的紀錄只保留在生涯，不混入近期。
- 生涯頁保留 Hunter 既有來源及每場詳細對戰卡；PK 沿用獵人交鋒獨立入口。家庭代報名保留在賽程，以參賽者標示，孩子不併入本人戰績。
- 讀取失敗不顯示零戰績，部分讀取明列未核對賽事。名次不由勝敗推估：優先用本人原始天梯入帳的名次；一般賽或未入帳者只接受公開已完賽的冠亞季殿欄位，且必須與 Hunter 已辨識的本人賽內 ID 唯一一致。缺來源明示未記錄名次。
- 正在參加只列非取消且等待／進行中的報名；完整我的賽程維持原有分類。上場提醒共用既有 20 秒 timer，同房家庭成員共用一次摘要讀取，切換生涯頁或背景後不繼續刷新。
- 賽事展開使用既有以 UID 區隔的 fold storage。重新登入可回復個人中心分頁。

## 驗證

- 個人中心、更正／撤銷、缺資料、家庭隔離、Hunter B1/B6/H2H、queue dashboard/refresh 與本人天梯讀取／名次核對共 121 項 Node tests 通過。
- production frontend verifier、JavaScript syntax、git diff whitespace 檢查通過。
- 真實 profile renderer 與 action 分支的 fixture 在 320/390/430/768px 完成期間切換、賽事展開及橫向溢出檢查。這不是正式帳號實測；runtime 缺繁中字型，截圖不代表中文字型實機驗收。

## 發布前待驗收

使用真實帳號核對本人／家庭報名、各主題文字樣式、舊資料涵蓋率及手機現場上場提醒。單場原始入帳、名次及結算狀態已接線；來源缺失、讀取失敗、多筆入帳分開顯示。尚需以真實帳號確認歷史文件完整程度。先建立草稿 PR，不合併部署。

## 單場成績來源與讀取

展開賽事後才查一次該場公開摘要與本人 ladderTransactions。新唯讀 getMyLadderEventResult 永遠使用登入 UID + eventCode + type=event 三個 equality 條件；管理員查看自己的個人中心也不查全站紀錄。最多取兩筆，兩筆以上顯示需核對，不選一筆冒充正確結果。回傳僅包含原始入帳分數、名次、賽季與時間，不包含其他玩家及操作人資料。沿用現有 Firestore 本人讀取規則，沒有權限或 schema 變更。

單場顯示「本場原始入帳」，人工更正另列天梯紀錄，不把未關聯的調整硬加到活動。確定入帳零分顯示 0 PT；查無紀錄、網路失敗、一般賽與全場已結算但本人未查得紀錄各自顯示。舊紀錄缺少有效房號時保留對戰，停用入帳核對。請求以 UID + 登入 epoch 隔離，具 10 秒讀取逾時、同場去重與手動重試。
