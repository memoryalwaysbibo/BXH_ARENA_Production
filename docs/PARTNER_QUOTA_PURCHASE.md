# 活動主辦加購場次入口

有效簽約的活動主辦可從「賽事管理 → 我的合作方案」進入「購買場次」與「我的訂單」。手動授權不顯示加購入口；合約到期或離開主辦模式後不再允許進入。

購買頁沿用 commerceService 的 catalog/create-order 與既有訂單、轉帳回報和最高管理員對帳流程，只列出 room_quota 且 audience=signed_organizer 的商品。一般商城仍只顯示 skin/item，VIP 與場次不會重新出現在一般分類。價格、商品版本、合約資格與是否能購買均由後端確認，前端不自行加額度。

尚未開店、沒有上架方案或交付能力未驗證時，顯示相應訊息，不建立虛構商品，也不開放付款捷徑。商品分頁即使當頁沒有場次商品，仍保留載入更多入口。訂單頁仍顯示同一帳號的完整歷史，包含舊合約訂單。

主辦模式、合約或登入身分變更時會隔離商品與訂單快取，丟棄舊請求回應。連線中斷的場次訂單保留原操作識別碼與原合約代碼；更換合約後不能直接重試，需先查看自己的訂單或聯絡 BXH 確認。

## 尚未完成的可用場次串接

本變更完成入口與既有訂單介面的銜接，沒有完成購買額度的實際消耗機制，不能視為已開放販售。

現有 commerce 後端交付只會寫入獨立 commerceEntitlements；建房與正式開賽尚未讀取此權益。我的合作方案目前仍顯示原 partnerContracts 的 includedEvents/usedEvents，因此不會將商城帳本數字冒充為已可使用場次。也不修改已簽署合約內容、期限或使用紀錄。

正式開放前，需完成購買權益的查詢、可用總額顯示、實際建房或開賽時的原子扣用、重試防重扣及未使用權益退款串接。扣用時點必須依既有合約的 creation-v1/start-v1 與加購條款明確決定，不得把舊合約靜默轉成新政策；後端也應比對下單時預期合約，避免合約在請求途中更換。

完成上述驗證後，才可設定實際商品、價格、銀行收款資訊與已驗證的交付能力。此 PR 不變更任何正式資料、價格或開店設定。
