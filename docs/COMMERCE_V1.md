# 商城第一版：人工轉帳候選

本變更是可審查的前端候選；配對後端為 `BXH_ARENA_Functions_Production/release/commerce`。版本為 v14.3.37／build 20261028.1，須先驗證後端閉店部署再發布前端。沒有正式商品、價格、收款帳戶或交付能力設定；未開放時清楚顯示「商城準備中，目前尚未開放購買」。

## 入口

- 玩家主選單「商城」→ 商品分類 → 清單 → 詳情（照片／說明／資格／期限／條款）→ 建立訂單。
- 個人選單「我的訂單」：查看付款及交付兩種狀態、匯款帳號快照、回報末五碼與台灣轉帳時間、取消尚未回報的未付款訂單。
- 最高管理員「商城管理」：商品草稿與上下架、訂單／對帳、交付重試、收款設定、全額退款登記。V1/V2 管理導覽共用相同權限。

## 人工確認

玩家回報資料不等於付款成功。管理員在銀行確認入帳後，輸入實收金額及唯一銀行交易識別碼，再確認收款。須固定用同一筆銀行紀錄的識別碼，系統才可阻擋同筆入帳重複核銷。少付／多付／重複匯款先人工釐清，不能強行改寫原成交金額。

付款與交付分開記錄；交付失敗不會回到未付款。待確認的寫入保存在帳號範圍內的 sessionStorage，斷線重試沿用原操作 ID。換帳號及登入工作階段變更會清除畫面快取。後端仍是權限與防重複的最終準據。

退款第一版只支援全額：先收回尚可自動逆轉的權益／停止待交付訂單，於銀行完成退款後登記退款交易。已使用或有後續異動的權益必須另行審核，不提供強制刪除。沒有自動匯款、部分退款、購物車、錢包、優惠券或自動續訂。

## 商品與功能串接

商品草稿支援 `room_quota`、`vip`、`skin`、`item`。後端的交付能力預設關閉，須在各功能實際使用及退款整合完成並驗證後才能上架。權益帳本本身不代表既有卡冊、Skin 裝備、VIP 功能或正式開賽已串接。

開房次數僅有效簽約主辦可買，購買額度獨立保存、不改寫已簽合約。未來須由正式開賽的原子扣次流程承接；建房及報名不扣購買次數。VIP 從成功交付計時，續購延長現有有效期限。Skin 持有期限由商品設定，第一版不實作玩家交換。

## 驗證

`node --test tests/commerce-ui.test.cjs`

`node tests/commerce-browser.cjs`（需 Playwright Chromium；可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定本機瀏覽器）

`node scripts/verify-production-frontend.cjs`

瀏覽器測試使用隔離假資料與服務替身，測試 390px／1280px 的購買、匯款回報、對帳及設定操作；實際資料庫交易由配對後端 Emulator 測試驗證。未登入正式帳號、未寫正式資料、未測真實付款。

既有 `tools/verify-management-v2-migration.cjs` 是歷史遷移快照驗證；本次變更前的 `5bda603` 即有三項失敗（導覽雜湊、舊入口雜湊、已隱藏獵人占位群組）。本次保留其歷史基準，不更新為虛假的通過結果。新增導覽權限由商城測試另行覆蓋。
