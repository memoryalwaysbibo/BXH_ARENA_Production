# PASS 回補與空台接手修正

適用一般、積分及玩家一般的單淘汰賽；其他賽制保留既有流程。

## 行為

- PASS 固定等待當輪可替代場次完成，原台優先，原台忙碌時安排最久空閒的可用台。同時可回補者依條件達成時間排序。
- 上一輪仍有未開始場次時維持輪次閘門；不以未來輪次作為 PASS 前置條件。
- 最後一場沒有可替代場次時拒絕 PASS，提示改用暫停，避免留下無法恢復的排程。
- 回補保留比分、失誤與歷史，避開進行中、暫停、離線待同步、退場及人工保留的場次。
- 人工指定回補台後等待該台；雲端裁判席位、派發版本及比分版本檢查維持有效。
- 舊 manual-only PASS 於下一次權威排程重建時恢復；玩家 CALL/PASS 的固定等待條件仍保留。
- 空台及等待晉級的裁判台提供「可接手場次」，列出不可接手原因；PASS 清單顯示原台、目標台、等待分鐘及「指定回補台」。
- 回補後提供「重新通知選手」；按鍵沿用既有通知服務，確認狀態明示為本裝置。

## 驗證

- 新增 28 項領域與 UI 單元測試通過，含完整 24/128/320 人賽程、原台回補、空台補位、人工指定、版本衝突與紀錄保留。
- 核心 critical 回歸全數通過。
- 原裁判席位、計分、派台及賽事完成測試通過；凍結的社群裁判候選包核對通過。
- 新增手機與桌面 Chromium 控制項測試至 CI；本機 Chromium 因執行環境 socket 限制未能啟動，不能算瀏覽器驗收通過。

## 發布界線

前後端必須一起發布。沒有新增輪詢、計時器或額外 Firestore 查詢，回補沿用既有權威排程交易觸發；完全沒有新的雲端事件時，不宣稱會自行喚醒舊資料。

此修正尚未部署正式站。正式站的函式來源與 repository 存在已知差異，必須從現行 commitRefereeCommand 套用經核對的差異，保留其餘匯出及部署設定，不能直接覆蓋整包。
