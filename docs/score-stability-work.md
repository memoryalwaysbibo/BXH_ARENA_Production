## 驗收原則

- 每個已確認操作僅生效一次；失去回覆不代表未寫入。
- 加分、失誤與撤銷不寫整份房間或公開戰況文件。
- 公開戰況可以延後，但不能以舊版本蓋回新比分。
- PASS、晉級與派台保留受影響場次的一致性與既有派台規則。
- 壓力測試量測成功／失敗、p50/p95/最慢、重試次數與每筆最終結果。
- 不以單元測試或 Emulator 速度宣稱正式環境容量；切換與回復須保留最新比分。

目前交付：故障證據與缺口盤點、診斷原因修補，以及分桶候選版裁判 PASS
後端與前端路由。PASS 沿用既有 scoring engine，將派台版本、比分、公開
投影、收據與稽核紀錄一起提交；前端以派台版本確認完成，同一筆收據重播
不再跳過一次。6/12 台測試涵蓋保留其他桶比分、下一場派發、公開投影、
重播、失效權限、版本過期、保護場次與缺桶拒絕。這仍是全房結構交易，
不宣稱降低了 PASS 的競爭或已解決正式環境的一分鐘等待。
尚未交付：全部六項上線、正式容量驗證或已證實的故障根因。

這些修正未改變 PASS 執行範圍，也不代表已消除等待。PASS 目前呼叫
scoring-core.transition → engine.markMatchSkipped → rebuildCourtAssignments，

把它改為只讀本台桶，否則未讀到的其他台 pause/resume、比分或派台狀態
可能使全房重建與寫回失去一致性。

後續實作順序：先明列 PASS 與派台所依賴的場次狀態及版本，再建立只提交
受影響場次的結構路徑；一般送分與公開戰況各自確認。驗收必須涵蓋 PASS
與其他台送分／暫停／完成同時發生、舊版本拒絕及同收據重播。完整頁面
驗收仍待新 CI 跑到該步驟；正式站與房間開關均未修改。
