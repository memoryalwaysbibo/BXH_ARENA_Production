# 獵人執照 2.0 — B1 驗收說明

本批次統一統計口徑、顯示資料讀取狀態，並將現行「得分效率」更名為「得分占比」。評分權重、階級門檻與八角圖比例維持現行版本。

## 玩家驗收

1. 開啟獵人檔案。載入期間僅顯示讀取狀態，不先顯示 LV.1 或零戰績。讀取失敗時顯示重新整理入口。
2. 無戰績帳號顯示「尚無已完成對戰」。能力百分比沒有分母時顯示「—」；有樣本但該方式未出現才顯示 0%。
3. 檢查資料覆蓋說明中的總場数、可分析場數及有效回合。快速判定保留勝敗，但不產生比分、攻防分布或有效回合。
4. 若賽事或本人報名資料讀取失敗，或公開資料缺失／身分無法確認，顯示實際原因及賽事數。保留已讀取統計，暫停整體評分、評級與戰型結論。
5. 比較總覽、能力分析與對手分析的有效回合。四種結束方式的事件只在整份回合帳與最終比分一致時納入。失誤判罰參與比分核對，不算四種結束方式。
6. 同場重複紀錄只計一次；較新確認或更新的紀錄取代舊版本。最新版本明確標示未完成時不保留舊勝場。重新整理時從現存已完成比賽重建，不累加舊快取。

## XP 與歷史紀錄

保留原有 XP 計算及 +10／+2／+20 規則；回合 XP 沿用既有可分析紀錄中的事件數，包含失誤判罰。畫面改稱「回合經驗事件」，避免與只計四種結束方式的「能力有效回合」混淆。沒有重置生涯、修改既有永久成就或寫入新資料集合。

取消的報名不再直接抹除已完成歷史對戰；實際計數仍只接受來源建立器提供的已完成、非輪空 Match。

- `node --test tests/hunter-b1-statistics.test.cjs tests/hunter-b1-cloud.test.cjs`：12 項測試，涵蓋更正／撤回、去重、比分及回合核對、判罰、快速判定、讀取缺失與畫面狀態。
- `node scripts/run-regression-core.cjs critical`：核心回歸，含上述 B1 測試。
- `node scripts/verify-production-frontend.cjs`：前端完整性檢查。
- `node tests/hunter-license-grade.test.cjs`、`node tests/enchantment-hunter-ledger.test.cjs`：既有階級及附魔帳目相容性。
- 使用正式 renderer／CSS 和模擬戰績，在 390px Chromium 檢查正常、空資料、部分缺失、載入及失敗五種畫面；均無水平溢出。此檢查不是登入後的真實帳號驗收。

## 已知邊界

目前資料入口仍以可查到的公開賽事及本人報名文件為範圍。非公開、已刪除或未被此入口發現的歷史資料不會憑空補算；「戰績已讀取」代表已發現來源完成讀取，並不保證涵蓋所有過往賽事。正規／PK／附魔分流及新實力模型留待 B2／B5。
