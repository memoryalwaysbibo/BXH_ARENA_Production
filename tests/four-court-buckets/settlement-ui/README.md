# Certified ranked bucket completion handoff

Depends on the ranked settlement backend candidate in PR713. No deployment, rollout configuration, runtime flags or room activation is included.

Bucket rooms enter the new path before every legacy completion check and local lifecycle mutation. The cloud adapter first reads both roots and all active buckets in a Firestore server transaction. A completed certificate must match the room ID, code, epoch, every bucket revision, both private/public completion markers, ladder results and SHA-256 of the exact canonical state. Only then does the UI replace its local snapshot. The callable response alone is never proof of completion. An incomplete first read calls the existing ranked settlement endpoint once and repeats the transaction, including after a lost response. Refresh can read the same completed certificate without a callable. No browser cloud writes, legacy archive fallback or pending-write retry queue are used.

A switched account, room, epoch, migration/deletion marker, stale projection, corrupt/missing bucket or mismatched certificate keeps completion unacknowledged. The UI does not reset a backend award, manufacture timestamps or overwrite the canonical results. Local storage/index failure is reported separately after cloud confirmation. Ordinary unmarked rooms retain the original completion path. General/non-ranked bucket completion remains unsupported; the backend rejects it and the UI does not fall back to legacy writes.

Validation: run `node tests/four-court-buckets/settlement-ui/probe.cjs` (36 cases). CI runs Chromium on desktop and mobile viewports (16 cases). The browser test executes the actual app archive functions and cloud adapter with an isolated SDK/auth boundary. This is not a full page, real Auth/App Check, real Firestore transaction or production acceptance test. Those, general completion, hosting records, remaining writer review and controlled cutover/rollback are still required before enabling rooms.

The browser SDK exposes no document createTime. Physical generation is therefore bound to the unique manifest epoch and room ID; the certificate sourceCreatedAt and hash are backend-issued, and no client can write these protected roots. Backend PR713 separately verifies SDK createTime against the certificate. Epoch reuse is prohibited by the existing migration protocol.
