# Certified ranked and general bucket completion handoff

Depends on the closed backend candidates PR713 (ranked) and PR715 (general). No deployment, rollout flags or room activation is included.

The current page pins code, room ID, epoch and ladder mode. A server transaction reads both roots and every active bucket. Private/public certificates, the complete revision vector and canonical-state SHA-256 must match before the app adopts a completed snapshot. Ranked calls send `expectedRoom: {roomId, epoch}` through the existing callable wrapper; general calls use `completeBucketTournament({code, roomId, epoch})`. A mode change stops before calling either endpoint. The backend separately enforces generation and current authority; a callable response alone never acknowledges completion.

Lost response is followed by fresh readback. Refresh can acknowledge an existing certificate without another call. Account/room/epoch changes discard the result. Migration/deletion presence, stale public vectors, missing/corrupt buckets and unverified award/archive flags stop without legacy fallback. Local obsolete ladder fields/certificates are removed when adopting a canonical general result. Storage/index failure does not trigger cloud writes or duplicate awards. General rooms show completion without claiming ladder points. General UI allows existing operators; the backend still restricts mutation to the current active manager. Ranked completion remains admin-only. Unmarked legacy completion retains its original path.

Validation: `node tests/four-court-buckets/settlement-ui/probe.cjs` (58 cases); Chromium desktop/mobile runs both modes (32 cases). These execute actual app archive functions and cloud adapter with fixture SDK/auth boundaries. They do not constitute a full page, real Auth/App Check, real Firestore transaction or production acceptance test. Backend Emulator suites cover actual transaction boundaries independently. A further 24-case browser integration check uses the actual pinned PR713/PR715 handlers and QR proxy for 4/6/12 courts, both modes, lost response after commit, and read-only repeat acknowledgment. CI materializes the exact two backend commits into isolated checkout paths; SDK transport/auth/clock remain fixtures, so this is still not real sign-in or full-host acceptance.

The web SDK does not expose root createTime. Readback relies on the unique epoch/room ID, trusted protected certificate and digest; the backend checks actual SDK createTime. Epoch reuse is prohibited by the migration protocol. Remaining acceptance includes exact live syncMyHostingProgress source review, broader writer/derived-consumer coverage and six-court cutover/rollback.
